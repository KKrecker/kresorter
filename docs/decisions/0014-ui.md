# 0014. Desktop window: PySide6 as an optional extra, the CLI's services, two languages

- Status: proposed
- Date: 2026-11-02
- Builds on: 0001 (items 1, 4, 5), 0004, 0008, 0009, 0010, 0011 (item 5), 0012, 0013
- Amends: 0011 item 5 (the consent to the machine scope is remembered by the window's
  settings), 0013 item 21 (the modules of `safeclean.ui` import `llm`)

## Context

Step 7 adds a desktop window over what the command line already does: scan and analysis,
the quarantine with restore and purge, organize with undo, autostart, recovery and the local
explanations. Nothing new is decided about files: levels, plans, refusals, the journal and
recovery stay those of decisions 0004 to 0013, and the window calls the same functions in the
same order as the CLI, under the same journal session. What is new is how they are shown,
confirmed and run without freezing a window, the settings the window remembers, and its
two languages.

The toolkit is Qt for Python (PySide6, LGPL), an optional extra: `pip install safeclean`
stays without dependencies (0001 item 5) and every command works without Qt. Only
`PySide6-Essentials` is needed (QtCore, QtGui, QtWidgets); the window uses no web engine and
no network module of Qt. On Linux, Qt needs the system's EGL and OpenGL libraries even
offscreen; CI installs them. Packaging (installers, bundles, signing) is step 8.

The look is the one approved on the prototype: a white canvas, warm grey surfaces and
borders, one blue accent, the system font, an 8 px spacing grid, radii of 8 to 12 px, borders
rather than shadows, and a dark palette when the system is dark. Levels have one colour each
(green safe, blue likely safe, orange review); red is reserved for permanent deletion.

Organize's category directories keep their names on disk, English and fixed since step 5
(0012 item 23), in either language of the window: the CLI, undo, recovery and the folders
sorted before all know them by those names. The window names each category in its language and
shows the directory beside it (item 44); directories named in Russian on disk would be a second
table, which neither the commands nor a folder sorted by them would know.

Every numbered item below is a behaviour a test can show, and is cited by one (item 43). What
cannot be tested (context, the step plan, limitations) is prose. An item is cited only by
tests that show all of it, so it leaves the pending list in the one commit that completes it
(the table in the step plan).

## Principles

1. **The core has no dependency.** `dependencies` in `pyproject.toml` stays empty; no module
   outside `safeclean.ui` imports `PySide6` or `shiboken6`, statically or by a literal name
   given to `__import__` or `importlib.import_module`; and the CLI runs every command with
   both made unimportable.
2. **Report first.** Opening the window, scanning, analyzing, planning and every listing
   delete, move and change no file the user has. Opening the window creates no data directory
   and no journal; an existing journal is opened only to look for unfinished work (item 25).
   Only the actions of item 3 act, and the journal is opened only by the pages and actions
   that need it, as the CLI's commands open it.
3. **Every action is confirmed.** Quarantine, restore, purge, organize move, organize undo,
   autostart disable and enable, and recover act only after a confirmation dialog that names
   the action and shows what it will do: the files with their count and total size, the
   entry and what is written, or the work recovery finishes. Cancel is the default button,
   Escape cancels, and a dialog closed any other way acts on nothing.
4. **Review is never preselected.** When findings are shown, the Safe ones are selected and
   the others are not. Selecting a whole level or a whole group selects only findings the
   analysis proposes (`Finding.proposed`): never a Review finding, never the kept copy of a
   duplicate group. A Review finding is selected only by its own check box.
5. **Red only for what cannot be undone.** Purge is the only action drawn in the danger
   colour; its dialog says the files are deleted permanently and cannot be restored, and its
   button reads "Delete permanently". No other control uses the danger colour.
6. **The CLI's services.** The window makes its contexts only through `Environment`
   (`safeclean.environment`, pre-step-5 audit B8) and runs the domain functions the CLI runs,
   under the journal session of item 11. On the same tree, the window's findings and levels
   are those of `analyze --json`, its organize plan is that of `organize move` without
   `--yes`, and its autostart entries are those of `autostart list --json`.
7. **No program, no connection, no console of its own.** From PySide6, `safeclean.ui`
   imports only `QtCore`, `QtGui` and `QtWidgets`, and never `QProcess` or `QDesktopServices`
   (which opens files and addresses with other programs). Explanations come only through
   `llm`, the one network point (0013 item 7); the guards of 0013 items 2 and 7 read
   `safeclean.ui` like any other package, and 0013 item 21 is amended so that the modules of
   `safeclean.ui` may import `llm`. No module of `safeclean.ui` imports `safeclean.cli` or a
   `safeclean.cli_*` module.

## Installing and starting

8. **An extra and two entry points.** `pyproject.toml` has the extra `ui` with
   `PySide6-Essentials>=6.8,<7`; `dev` has it too, with `pytest-qt`. `safeclean-ui` (a GUI
   script) and `python -m safeclean.ui` call `safeclean.ui.launch.main(argv=None, *,
   environment=None) -> int`, which opens the window and returns 0 when it is closed.
9. **Without PySide6, one line.** When PySide6 cannot be imported, `main` writes one line on
   stderr that names `pip install "safeclean[ui]"`, creates nothing and returns 3.
10. **CI runs the window's tests.** The workflow installs the system libraries Qt needs on
    Linux (`libegl1`, `libgl1`, `libxkbcommon0`, `libfontconfig1`, `libdbus-1-3`) before
    the package, and the tests run with `QT_QPA_PLATFORM=offscreen` on every Python of the
    matrix.

## What the window shares with the CLI

11. **One journal session.** The session the commands that act share (the data directory
    checked before anything is created in it, the single-instance lock, the journal opened
    there) moves from `cli_journal` to `storage.session`, which reports why it could not run
    as a value (`SessionFailure`: `data_dir`, `locked`, `data_dir_os`, `journal_open`,
    `stopped`, `journal_failed`, with the detail). The CLI renders each as before, with the
    same messages and exit codes; the window shows them in its words.
12. **What the window needs moves out of the CLI.** `analyze_paths` moves to `analysis.run`;
    the choice of what changes autostart entries on a platform (`changes_for`) to
    `autostart.changers`; the listing of quarantined files to `quarantine.journal`
    (`quarantined(conn)`, by id). The CLI calls them where it computed them; its output is
    unchanged.
13. **Recovery first, as the CLI.** Every session the window opens for a domain recovers the
    interrupted work of that domain first, as the domain's command does, and an action refuses while
    another domain's work is unfinished, without acting. The window's Recover runs what
    `safeclean recover` runs, for every domain.
14. **Plans made again under the lock.** What the user confirmed is carried out only as far
    as it still holds inside the session: the quarantine moves the files confirmed, each
    checked again at move time (preflight, 0004); organize moves only the confirmed moves its
    plan, made again inside the lock, still contains unchanged (same file, same destination);
    restore, purge and undo act only on the confirmed items their plans still contain. What
    no longer holds is reported, not acted on.

## Running work

15. **Off the window's thread.** Scanning and analysis, every journal session, planning,
    acting, recovery and explanations run in a worker thread; the window keeps handling
    events while they run, and their results are applied in the window's thread. The journal
    connection is opened, used and closed in the worker.
16. **One task at a time.** While a task runs, every control that starts a task is disabled
    and the window says what runs; when it ends, they are enabled again. An exception in a
    task is shown as an error with its message, and the window stays usable.
17. **Closing waits for what acts.** Closing the window while a task that opens the journal
    runs is refused with a message naming it; after it ends, the window closes. A task that
    only reads (scan and analysis, explanations, the explanation check) does not hold the
    window: it is left behind when the window closes.

## Pages

18. **Navigation.** A sidebar opens Overview, Findings, Quarantine, Organize, Autostart and
    Settings, in that order, with the current page marked; every page is reachable with the
    keyboard, and every button has a text or an accessible name.
19. **Overview.** The folders to scan are the safe zones of the policy (`default_roots()`)
    plus folders the user adds, which can be removed again; Scan runs scan and analysis with
    the default thresholds. Afterwards it shows, for each level, the files and their size, the
    number of duplicate groups and of skipped paths, and, when the open-file check is not
    reliable, that files in use cannot be recognized.
20. **Findings.** Grouped by their strongest reason, each group with its count and size;
    filters by level (all on at first) and a search that keeps findings whose path contains
    the text, ignoring case; a detail panel for the current finding with its path, size,
    modification time, level and every reason with its detail. The bar under the list shows
    the selected count and size; "Move to quarantine" is enabled only with a selection.
21. **Quarantine from the findings.** After confirmation the selected findings are
    quarantined (item 14); the result shows what moved (count and size), each refusal with
    its reason, and the error that stopped the batch, if any, with the files that had moved
    put back. Findings that moved leave the list.
22. **Quarantine.** The quarantined files (id, original path, size), from the journal;
    Restore and Delete permanently act on the selected ones after confirmation (purge's plan,
    with the total size, is shown first), and the result shows what was restored, deleted and
    freed, and each refusal with its reason.
23. **Organize.** Where organize does not move files (0012 item 37: not Linux, or no reliable
    open-file check), the page shows why and offers nothing else. Elsewhere: a folder is
    chosen, its plan shows the moves by category and the files that stay with their reasons,
    and after confirmation the batch is carried out (item 14); the result names the batch.
    The batches are listed (id, time, kind, files moved, state, folder), and Undo shows the
    undo's plan, then acts after confirmation.
24. **Autostart.** The entries grouped by source, each with its state, scope and location;
    Disable or Enable for an entry that can change (`disableable`), after a confirmation that
    says what is written, as `autostart disable` without `--yes` does. The result shows done,
    refused, rolled back or failed, and a failed change names Recover.
25. **Unfinished work.** When a session finds unfinished work, and when the window opens on
    a journal that has some, a banner names the domains and offers Recover; after recovery
    it shows what was closed, as `safeclean recover` reports it.
26. **Explanations, on request.** The detail of a finding, an autostart entry and a file
    organize leaves in place has "Explain (local AI)": it asks for the one subject of that
    result (`llm.subjects`, 0013 item 17) through `llm.explain`, and shows the answer under a
    label that names the model and says it may be wrong, or why there is none (0013 item 23,
    in the window's words). Nothing is asked without the button, nothing is stored, and an
    answer changes no level, selection, plan or action.
27. **Settings.** The language (a change applies the next time the window opens, and the
    page says so), the machine scope of autostart (on Windows only, item 37), a Check of the
    local AI that runs the checks of `safeclean llm status` and shows each, and the data
    directory's path, read only. The page says when the settings file was not used (item 36);
    the file is written only when the user changes a setting.

## Languages

28. **Every text in English and Russian.** The window's texts come from one catalog with an
    English and a Russian text for each key; a test fails on a key without both, on an empty
    text, and on texts of one key whose placeholders differ.
29. **Counts in each language's forms.** English has one and other; Russian has one, few and
    many (1 файл, 2 файла, 5 файлов, 11 файлов, 21 файл, 22 файла, 111 файлов).
30. **Which language.** The setting (`system`, `en`, `ru`); with `system`, Russian when the
    system locale's language is Russian, English otherwise. It is chosen when the window
    opens.
31. **Every value shown has a label.** Each member of the enumerations the window shows
    (`Level`, `Evidence`, `RefusalReason`, `BlockReason`, `SkipReason`, `RestoreRefusal`,
    `PurgeRefusal`, `StayReason`, `FolderReason`, `UndoReason`, `Blocker`, `BatchKind`,
    `BatchState`, `Source`, `Scope`, `ChangeState`, `ChangeRefusal`, `Domain`,
    `Unavailable`, `SessionFailure`) has a label in both languages. Paths (with the category
    directories in them), names of files and entries, details from the system and explanations
    are shown as they are; what names a category is item 44.

## Look

32. **The tokens** are those of the table, in `ui.theme`; the window's style sheet uses no
    other colour. `accent` marks the current page, the selection and the focus; text and the
    primary button use `accent text`. A level's badge is its text on its background, its dot
    the level's colour; `danger` is the purge's alone (item 5).
33. **Readable.** Text on canvas, surface and surface 2, secondary text and accent text on

34. **The system decides light or dark.** The dark palette is used when Qt reports a dark
    colour scheme and the light one otherwise, and a change of the system's scheme while the
    window is open is applied at once.

## Settings

35. **One small file.** The window remembers only `settings.json` in the data directory, a
    JSON object with `language` (`system`, `en`, `ru`) and `include_machine` (a boolean). It
    is written only when the user changes a setting, after the data directory is checked
    (0009), through a temporary file renamed over it, private (`0600` on POSIX). No finding,
    path, plan or explanation is stored by the window.
36. **A broken file is not trusted.** A missing file means the defaults (`system`, `false`).
    An unreadable file, invalid JSON, a value of the wrong type or unknown means the defaults
    too; the Settings page says the file was not used, and the file is not written until the
    user changes a setting. Unknown keys are ignored.
37. **The machine scope is remembered** (amends 0011 item 5). On Windows, `include_machine`
    makes the Autostart page read the machine scope, as `--include-machine` does; it is off
    by default, and turning it on asks for confirmation that says what is read. The CLI still
    reads the machine scope only with `--include-machine`.

## Testing

38. **Real threads, offscreen.** The window's tests run with `pytest-qt` on Qt's offscreen
    platform, which the tests' `conftest.py` sets; tasks run in the real worker thread. Pages
    receive the dialogs that would block (confirm, choose a folder) as functions that tests
    replace; the real dialogs are tested on their own.
39. **No live system.** The window's tests use environments made for `tmp_path`, as the
    CLI's tests do: none reads or changes the user's home, autostart or registry, and the
    network guard of 0013 item 29 applies to them.
40. **A launch without a display.** `safeclean.ui.launch.main` opens and closes the window
    in a test, and `python -m safeclean.ui` runs it.

## Organize's categories

44. **A category in the window's language, its directory by its name on disk.** Each category
    of organize's table has a label in English and in Russian, and no other name has one; the
    English label is the name on disk, and no two labels of a language are the same. A plan's
    group names its category by the label and, when the label is not the name on disk, the
    directory beside it (`Изображения (папка Images): 1 файл, 5 Б`). Everything else keeps the
    name on disk: each line of the plan and of the confirmation (`a.jpg → Images/`), the
    batches, undo and the reasons, as paths. The directories the window makes are those the CLI
    makes, in either language, so `organize undo --yes` moves back a batch of the Russian
    window. A name without a label is shown as it is. The README says that the directories keep
    their English names in every language.

## Accepted limitations

- **The language applies on the next start**, not at once.
- **Default thresholds only**: the window analyzes with the defaults of `analysis.size_age`;
  `--large` and `--older-than` stay the CLI's.
- **A scan cannot be stopped**; closing the window leaves it behind (item 17).
- **The settings of the local AI** (address and model) come from the environment, as for the
  CLI (0013 items 8, 9); the window shows them and has no field to change them.
- **No "show in folder"**: opening a file manager would launch a program (0013 item 2); a
  path can be copied instead.
- **Category directories keep their English names on disk** in the Russian window too (item
  44, 0012 item 23): only what the window shows of a category is translated.
- **Two windows act one after the other**: a second window can be opened, and the
  single-instance lock lets only one session act at a time; the other shows that the journal
  is in use.
