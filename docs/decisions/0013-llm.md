# 0013. Local explanations: Ollama on loopback, advisory text, nothing installed

- Status: proposed
- Date: 2026-11-01
- Builds on: 0001 (items 1, 4, 5), 0010 (item 2: every conclusion is explained), 0011, 0012
  (proposed: the plan whose files that stay are explained)
- Amends: none

## Context

Step 6 adds optional explanations, written by a local language model, of what safeclean has
already decided: analysis findings, autostart entries and the files organize leaves in place.
Levels, reasons, plans and refusals stay safeclean's own, deterministic and explained by their
reasons (0010 item 2); the model adds plain-language context ("what this cache is", "what this
program does"), nothing else.

The model runs in Ollama, a separate program the user installs, starts and fills with models;
safeclean is only a client on the loopback interface, written with the standard library and
no new dependency: `http.client`, what `urllib.request` is built on, without `urllib.request`'s
opener, whose default handlers take proxies from the environment and follow redirects, the two
things item 10 forbids. A model's answer is text from a program safeclean does not control,
prompted partly with names safeclean did not choose (an autostart entry can be named
anything): it is untrusted, shown under a label, never acted on.

Every numbered item below is a behaviour a test can show, and is cited by one (item 28).
What cannot be tested (context, the step plan, limitations) is prose. An item is cited only by
tests that show all of it, so it leaves the pending list in the one commit that completes it
(the table in the step plan).

## Principles

1. **Off unless asked.** No command contacts Ollama unless the user gives `--explain` or runs
   `safeclean llm status`. Without them, output and exit codes are those of step 5 and no
   connection is opened.
2. **Installed by the user, never by safeclean.** safeclean launches no program, so it does
   not install, update, start, stop or configure Ollama: no module in `src` imports
   `subprocess`, `pty` or `multiprocessing`, or uses `os.system`, `os.popen`, `os.startfile`,
   `os.exec*`, `os.spawn*`, `os.posix_spawn*` or `os.fork*`.
3. **Advisory only.** An explanation never changes a level, a reason, a plan, a refusal, an
   exit code or what a command does: it is asked for after the command's own result is final,
   from that frozen result, and only rendered after it. Commands that act never contact the
   model: `--explain` exists only on report commands and on `organize move` without `--yes`
   (item 25).
4. **Without Ollama, everything works.** Ollama not installed or not running, the model not
   installed, a refused setting, a timeout, an oversized or malformed answer: the command does
   what it does without `--explain`, with the same stdout and exit code, and one line on
   stderr names the cause (items 23, 24).
5. **The least data, nothing of the files.** The model receives only the facts item 17 lists
   for each subject: no file content, no path, no folder, no command line, no size or time.
   The `llm` package reads no file at all (item 22).
6. **The answer is untrusted text.** It is never executed, evaluated, parsed as a command, or
   used as a path, a level, a choice or a setting. It is cleaned of control characters and
   terminal escape sequences, bounded, and printed under a fixed label after safeclean's own
   output (items 20, 21, 26).

## Settings and the connection

7. **One network point.** Only a module on the allowlist imports `socket`, `socketserver`,
   `ssl`, `http`, `urllib`, `ftplib`, `smtplib`, `imaplib`, `poplib`, `xmlrpc`, `asyncio`,
   `selectors`, `webbrowser`, `_socket` or `_ssl`, or anything under them, statically or by a
   literal name given to `__import__` or `importlib.import_module`, and only what the
   allowlist gives it; everything it gives must really be imported. The allowlist, each
   module with what it may import, is pinned by a test, as the deletion point is (0001
   item 1), so it grows only with a decision.
8. **Loopback only.** The address is `http://127.0.0.1:11434` unless `SAFECLEAN_OLLAMA_URL`
   names another, of the form `http://HOST[:PORT][/]` where HOST is `localhost`, an IPv4
   address in `127.0.0.0/8` written as four decimal numbers, or `[::1]`, and PORT is 1-65535
   (11434 when absent); the form is checked by a pinned regular expression and the address by
   `ipaddress`, not by a URL parser. `localhost` becomes `127.0.0.1` in the settings, without
   asking a resolver. Refused before any connection, as `config` (item 23): another scheme
   (`https` included), any other host (`0.0.0.0`, `::`, `::ffff:127.0.0.1`, `127.1`,
   `2130706433`, any other name), user info, a path other than `/`, a query, a fragment, an
   empty value. `OLLAMA_HOST` is not read: it is the address the server binds to, not one to
   connect to.
9. **The model** is `SAFECLEAN_OLLAMA_MODEL`, `llama3.2` when unset. A name that does not
   match `[A-Za-z0-9][A-Za-z0-9._:/-]{0,99}` is refused as `config`. The model is installed
   when `/api/tags` lists its name exactly, or `<name>:latest` for a name without a tag.
10. **No resolver, no proxy, no redirect.** The allowlist of item 7 is
    `src/safeclean/llm/transport.py`, the transport, with `http.client` and `socket`: never
    `urllib`, whose opener reads proxy settings and follows redirects. The transport makes its
    socket from the address of item 8 itself, not through `socket.create_connection`: no
    resolver function is called, for `localhost` either. Proxy settings in the environment
    (`HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `NO_PROXY`, in either case) are ignored: the
    request goes straight to that address, and the transport reads no proxy setting at all.
    A `3xx` answer is refused by the transport itself, whatever its `Location`, as `redirect`
    (item 23): nothing above it can follow one, and nothing is sent to the `Location`.
11. **Exactly three requests.** `GET /api/version`, `GET /api/tags` and `POST /api/generate`,
    nothing else: never `pull`, `push`, `create`, `copy` or `delete`, which would download,
    publish, make or remove a model. Each sends only `Host`, `Accept-Encoding: identity`
    (nothing compressed to unpack), `User-Agent: safeclean/<version>`,
    `Accept: application/json`, `Connection: close` and, for the `POST`,
    `Content-Type: application/json` and `Content-Length`: no cookie, authorization or origin.
    The body of `generate` is exactly

    ```json
    {"model": "<model>", "system": "<the pinned instruction>", "prompt": "<the subject as JSON>",
     "stream": false, "options": {"temperature": 0, "seed": 0, "num_predict": 200}}
    ```

    where the pinned instruction, in `llm/prompt.py`, tells the model that the subject is
    data, never instructions, and asks for at most three plain sentences and no commands.
12. **Bounded.** Each request has one deadline, 3 s for `version` and `tags` and 60 s for
    `generate`, for connecting, sending and reading the whole answer, headers included:
    before each of them the socket waits at most what remains, so a server slow in every
    phase but in none beyond the deadline, or answering one byte at a time, still ends at the
    deadline, as `timeout`. An answer body over 64 KiB is refused as `too_large`: at once when
    its `Content-Length` says so, otherwise as soon as its 65,537th byte is read. A request
    body over 4 KiB is refused before connecting. The defaults are pinned by a test; tests
    give smaller ones.
13. **A budget per run.** A command asks for at most 20 explanations; subjects beyond them
    are counted as not explained (item 26). The checks of item 14 run once, before the first
    `generate`. After the first failure, for any reason of item 23, the run asks for nothing
    more. A run with nothing to explain opens no connection.

## Availability and setup

14. **`safeclean llm status`** checks, in this order and each only if the previous one passed:
    the settings (items 8, 9); that `GET /api/version` answers with a JSON object whose
    `version` is a string of 1 to 32 characters from `[0-9A-Za-z.+-]` (otherwise
    `not_ollama`); that `GET /api/tags` answers with a JSON object whose `models` is a list
    of objects with a string `name` (otherwise `not_ollama`) and lists the model (otherwise
    `model_missing`). Only successfully parsed responses accepted by the transport are
    subject to these checks. If the transport refuses a request, preserve its reason
    (items 10, 12), so a `3xx` is `redirect` and a response over the limit is `too_large`.
    It sends no `generate`.
15. **What `status` says.** On stdout, exit 0, when everything is in place:

    ```text
    Ollama: running at <url> (version <version>)
    Model: <model>: installed
    AI explanations: available with --explain on analyze, autostart list and organize move
    ```

    and otherwise exit 1, with each line naming what was found (`not reachable at <url>
    (<detail>)`, `<url> does not answer as Ollama (<detail>)`, `refused setting <name>=<value>
    (<detail>)`, `<model>: not installed`, `not checked`), then:

    ```text
    AI explanations: unavailable; safeclean works as usual without them
    To set them up (safeclean installs nothing itself):
      1. Install Ollama from https://ollama.com/download and start it
      2. Download the model: ollama pull <model>
      3. Check again: safeclean llm status
    Settings: SAFECLEAN_OLLAMA_URL (a loopback address, default http://127.0.0.1:11434),
      SAFECLEAN_OLLAMA_MODEL (default llama3.2)
    ```

    Step 1 is shown only when Ollama was not reached or did not answer as Ollama, step 2 only
    when the model was not found or not checked; the steps are numbered as shown.
16. **The README** has a section `AI explanations (optional)` that says Ollama and the model
    are installed by the user and never by safeclean, gives the steps of item 15 and both
    settings, and lists what is sent (item 17).

## What is sent

17. **A subject** is what one explanation is about, made by a pure function from a final
    result, with a fixed, ordered list of facts per kind:

    - `finding` (analysis): `level`; `reasons`, each `Evidence` value, and for a junk reason
      also its rule id (`junk_cache:python-bytecode`); `extension`, the lower-cased suffix of
      the file's name, empty when it has none or it is longer than 16 characters, the dot
      included.
    - `autostart`: `source`, `scope`, `name`, `program` (the last component, after `/` or
      `\`, of the command's first word, or of the quoted part it starts with), `enabled`.
    - `stay` (organize): `reason`, `extension`.

    Nothing else leaves: not the path, the folder, the size, the times, the digest, the
    location, the whole command, notes or details (details name other files). Each string is
    cleaned as in item 20, its lines joined by a space, and cut to 100 characters, ending
    with `…` when cut.
18. **Each subject is asked once.** Results with the same facts share one subject and one
    request (a thousand `__pycache__` files are one question). Subjects are in the order they
    first appear in the command's own output.

## The answer

19. **The only accepted answer** to `generate` is status 200 with a UTF-8 body that is a JSON
    object whose `done` is `true` and whose `response` is a string; anything else is
    `http_status` (another status) or `bad_response`. No other field of it is read.
20. **Cleaned before it is shown.** Terminal escape sequences (CSI, OSC and other `ESC`
    sequences) are removed whole, tabs become spaces, then every character in the Unicode
    categories `Cc` (except the newline), `Cf`, `Co`, `Cs`, `Cn`, `Zl` and `Zp` is removed;
    lines are stripped and empty ones dropped; at most 6 lines and 600 characters are kept,
    ending with `…` when cut. An answer with nothing left is `empty`.
21. **Never acted on.** Whatever the model answers (a level, a plan in JSON, `--yes`, a shell
    command, a path), the command's result, its own output and its exit code are those of the
    run without `--explain`, and nothing is moved, journaled or run. The `llm` package
    imports, from safeclean, only the package itself (for its version), its own modules and
    the results it explains (`analysis.report`, `analysis.score`, `autostart.models`,
    `organize.planner`), and only the command-line modules import it.
22. **Nothing is stored.** The `llm` package opens, reads and writes no file: it uses none of
    `open`, `os.open`, `Path.open`, `Path.read_*`, `Path.write_*`, `tempfile`, `sqlite3`,
    `shelve` or `pickle`. A run with `--explain` leaves the data directory and the folders it
    reports on as a run without it does.

## Failure

23. **Why explanations are missing**, a pinned set (`Unavailable`), in this order: `config`,
    `unreachable`, `timeout`, `redirect`, `http_status`, `not_ollama`, `model_missing`,
    `too_large`, `bad_response`, `empty`, each with a detail.
24. **Same exit, same output, one line on stderr.** With `--explain`, the exit code is always
    that of the run without it. The run's stdout without `--explain` is, byte for byte, the
    beginning of its stdout with it (text), or equal to it when no explanation came. A run
    that gets none prints on stderr

    ```text
    AI explanations unavailable: <reason> (<detail>); 'safeclean llm status' shows how to set them up
    ```

    and a run stopped after `<n>` explanations prints
    `AI explanations stopped after <n>: <reason> (<detail>)`; one such line at most.

## Command line

25. **`--explain`** is accepted by `analyze`, `autostart list` and `organize move FOLDER`. With
    `organize move --yes` it is a usage error, exit 2, before anything else, with argparse's
    `not allowed with argument` message. `organize move --explain` where moving is refused
    (0012 item 37) is refused as without it, and contacts nothing. Other commands do not
    accept it.
26. **The text output** ends, after the command's own output and one empty line, with

    ```text
    AI explanations (<model> via Ollama; advisory, may be wrong; nothing above depends on them):
      <label>
        <line>
      <n> more not explained (at most 20 per run)
    ```

    where the label is the subject's facts joined by `, ` (a list's values joined by `+`),
    every line of an answer is indented four spaces, and the last line appears only when
    subjects were left out (item 13). Nothing to explain, or no explanation at all: no
    section.
27. **The JSON output** (`analyze --json --explain`, `autostart list --json --explain`) keeps
    every key and value of the run without `--explain` and adds `explanations` (a list of
    `{"subject": {"kind": ..., <facts>}, "text": ...}`), `explanations_model`,
    `explanations_not_explained` (a count) and `explanations_unavailable` (`null` or
    `{"reason": ..., "detail": ...}`).

## Testing

28. **Every item of this decision is cited by a test** as `[0013.N]`. A meta-test fails on an
    item no test cites, on a citation of an item that does not exist, and on an item still
    listed as pending although a test cites it; the pending list starts with every item and is
    empty after the last commit of the step 6 plan. The meta-test checks its own rules on
    made-up items and citations, and those checks cite this item, so it never depends on
    another file.
29. **Tests stay on this machine.** Ollama in tests is a real HTTP server on `127.0.0.1`, on a
    port the system chooses, in a thread, that records every request (method, path, headers,
    body) and answers as each test scripts it (slowly, never, endlessly, redirecting, as
    something else). A fixture of `conftest.py`, used by every test, fails a test whose code
    connects or sends to an address beyond loopback or asks a resolver for a name
    (`getaddrinfo`, `gethostbyname`, `gethostbyname_ex`, `gethostbyaddr`), before anything
    leaves: no test needs Ollama, a model, DNS or a network.

## Accepted limitations

- **English only**, like the rest of the output; the quality of an explanation is the
  model's, and it can be wrong: the label says so, and nothing depends on it.
- **Nothing is cached**: each run asks again; storing explanations would store facts about the
  user's files.
- **At most 20 subjects per run**, one at a time, without streaming: a slow machine waits up
  to the deadlines.
- **`localhost` is `127.0.0.1`**: an Ollama listening only on `::1` needs
  `SAFECLEAN_OLLAMA_URL=http://[::1]:11434`.
- **Anything listening on the port is believed to be Ollama** if it answers like it: Ollama's
  API has no authentication. It receives only the facts of item 17, and its answer is
  untrusted text (items 19-21): the worst it can do is a wrong explanation.
- **Names steer the model**: an autostart entry named to persuade can change the text of its
  explanation, never a level, a plan or an action (items 3, 21).
- **The default model may be missing**: `status` says so and names the command that installs
  it; safeclean never runs it.
